机器学习入门实践——针对大一新同学的入门挑战

  • 周二： 补充任务，最终要产出一个ppt
  • 周二： 补充任务，要求同学使用git来管理代码，将代码上传到仓库，进行管理
  • 周三： 再次明确任务重点——— 简化代码
  • 周四： 同学已经完成了相关工作，代码控制到了3行内。布置新任务，要求复用代码到新任务

  • 两种教学模式的对比
    • 模式1：按部就班，先将原理，再让学生动手
    • 模式2：以任务为驱动，让学生通过解决问题来学习

写在前面-开放性思考题

  • 本科教育中，是否应当允许学生使用AI工具？该如何使用？该如何声明？（包括但不限于知识点自学、作业、小论文、毕设等）
  • AI编程的时代，程序员的核心技能点是什么？
  • 在AI的时代，从计算机人才培养的角度，有哪些知识技能可以弱化，哪些知识技能需要坚持打牢基础，哪些需要更加强化？
  • 计算机学科是一门技术更新极其快的学科，本科教育中如何更快地引入最新的技术？如何在坚守基础知识、基础方法、原理的同时，兼顾补充最新的技术？AI在计算机学科教学中，可以提供哪些帮助？

写作目的

AI浪潮下，很重要的是“与AI 共生”，即将AI当做工具和教练，“更理性、有效地使用AI”、“更聪明地利用AI强大自己”（selfpower）。除了常见的如何使用AI工具外，对于当下的教育，特别是本科计算机大类教育，笔者认为也应该主动拥抱适应AI工具，这样才能主动适应AI对教育的冲击影响，同时培养真正符合社会需要的人才。 对于AI教育，从纯知识的获取看，我认为只要恰当使用，AI是最好的老师，关键是：让AI不仅成为搜索引擎，更成为你的私人教练。我希望通过分享这个意外的教学实践，能让更多人看到新手利用AI进行自我提升的可能以及需要注意的一些问题，给本科教育一些参考。

当然，大学教育，我仍然认为是必不可少的，可以将AI自学和课堂教学结合起来。大学教育，核心是提供了：充满好奇和活力的年轻人交流的氛围和环境。其次，大学教育中具有约束力的、成体系的课程训练，也是走向专业化的重要辅助。（当然这两点要真正发挥作用，需要学校通过各类小组作业、竞赛、社团等营造跨学院的创新氛围，以及提高综合性、挑战性实践作业的难度）

背景

单位来了一名大一学弟（25年9月入学 软工），实习2周。个人比较热心，尝试着通过布置小任务的方式，用1周时间让其入门机器学习（了解其基本流程）。个人工作非常忙，所以每天抽出2次 * 每次10分钟指导一下，4个工作日后任务基本完成，让其通过一个ppt总结个人成果。虽然整个过程中使用的模型非常简单、准确率也不高，但是他通过这个过程了解了基本流程，对基本原理有个感性体会，并学会了使用AI来辅助编程、迭代代码。

主要结论

  • 因材施教，最好的老师，应当是教练，布置任务让学生自己完成，但是又不完全脱离，必要时干预和指点。
  • 不要让学生在一开始，因为环境配置、软件安装等环节挫败止步
  • 让学生有成就感，但更重要的是让他发现不完美、不满足的地方，不断迭代

附：教学案例实录

学生基础

1.性格比较内向腼腆，不属于那种非常有锐气、冲劲的，但是比较有毅力（成外毕业），同时主动实习主动性强。2.没有任何装软件的经验，也没有重装过操作系统等，仅下载过一次虚拟机，对于系统配置零基础3.不会科学上网，也不太想学4.编程IDE，使用过vscode，但都是默认配置

教学设计的理念

  • 特训班—— 以小任务为驱动，面向解决问题式的学习，而不是一上来先按部就班讲语法、讲各种算法题，让学生开始做算法题；
  • 教练，而非老师—— 关键过程看一眼，布置任务，关注过程和进展，而非盯着；
  • 因材施教，做得快，任务就多布置一点。做得慢，就少布置一点，根据学生的状态、心情来设计节奏。做完一个，追加一个。要通过不断的追问，让学生发现不完美的地方，每次追加的目标，刚好处在能跳起来够得着的位置，让学生处在有成就感但又不完全满足的状态。
  • 通过git tag等方式，让学生不断形成每次小的正反馈，培养小的成就感
  • 好的代码，应当是改出来的（从工作中产品迭代的角度看）
  • 不仅要自己能写代码，还要通过AI和重构拆解，学习理解陌生新代码
  • 没有按通用的教学过程，尽最大可能减少需要进行各类配置的操作，让主要精力、思维主线围绕着上层的任务，而不是工程部署细节。（当然会要求学生在完成任务后，再自行学习掌握环境配置的操作）
  • 习惯，很重要（好的开发习惯，会受益终生），一个好的开发习惯，比起直接的知识，对于新手在初期可能更关键
  • 工具： 使用最好用的工具（如vscode，cursor，gemini等）；
  • 学习代码重构迭代、代码复用，适应工作中的核心要求
  • 主动拥抱AI， 学会与AI协同，同时知道AI编程可能带来的风险和问题；
  • 基础知识，依然很重要，但是需要循序渐进，而且需要较长一段时间坚持。这里的特训，更多是帮助他快速入门，容易造成知识点比较零散，所以后续仍需要他自己梳理出重要的基础知识，再巩固，需要对学生进行强调；
  • 1周的学习，只能算入门，关键是养成习惯、培养兴趣

教学目的

  • 熟悉git，形成代码开发的成就感
  • 形成坚持不懈、持续优化的开发习惯——（日积月累，持续打磨）
  • 妥善管理代码
  • 以重构代码的方式，提升自己的编程技巧和习惯
  • 熟悉deepseek，cursor等，基于AI和GPT，自己去提问快速学习(self-power)，学习如何更好地vibe coding（与代码协同）

教学进展跟踪（迭代式追加任务，完成一个加一个）

任务概要总览： （1）利用AI编程，实现波士顿房价预测 （2）使用git管理代码，并将AI的程序进行拆解、简化 （3）将拆解后的代码，复用到新的问题：糖尿病预测问题中

周一： 17:00 发布任务(gitee, 数据集，deepseek)

周二： 补充任务，最终要产出一个ppt

【瓶颈问题】： 能通过deepseek，写出来代码，但是导入数据集和导入numpy包遇到了困难，代码非常复杂。而且一直没有解决数据加载问题。deepseek生成的代码中，手动生成模拟数据、手动实现numpy，deepseek回答越来越复杂。 问题原因： 提问方式不当，被AI绕进去了。AI过早地“灌输”了不属于这个入门级同学需要知道的细节； 指导干预：及时修改任务目标，将任务简化，让同学放弃导入数据集，直接使用本地csv（手动造少量数据），同时通过将代码拆解缩短，找出关键代码；

周二： 补充任务，要求同学使用git来管理代码，将代码上传到仓库，进行管理

【瓶颈问题】 在windows主机上，终端输入git指令还是有问题（环境变量配置），同时折腾了1个小时没解决，马上又临近下班，比较挫败 指导干预 ：让同学不要再管，我直接帮同学解决vscode中git配置问题

  • 成功解决git使用；
  • 教同学使用git 提交代码、给git 打标签（git commit， git tag） 以及回退到任意的提交（git checkout ）

同学感受

  • 能通过deepseek，写出来代码，同时通过问deepseek，学习了很多东西。
  • 在教练帮助下，赶在下班前 成功解决了git问题，比较开心 ** 及时干预**
  • 提醒同学，及时做笔记，立刻搜索查有哪些笔记软件？ 或者先写在本子上。要记录这些命令；

周三： 再次明确任务重点——— 简化代码

【瓶颈问题】：代码的结构太长 指导干预 ：使用notebook，对代码分块，理出基本逻辑

周四： 同学已经完成了相关工作，代码控制到了3行内。布置新任务，要求复用代码到新任务

【瓶颈问题】 配置conda环境出错，conda环境中确实某些包，无法继续运行 问题原因：

  1. 对于环境变量的理解、conda配置以及翻墙下载；
  2. gpt 提供的代码中，过于复杂，提供了非常多无关的包，导致环境管理相对比较复杂； 指导干预
  3. 帮他分析定位原因： git checkout 切换到上一个正确版本——> 定位是环境问题
  4. 尝试用旧的conda环境，发现不能解决
  5. 在vscode的terminal中， 使用power shell 不能成功，但是使用cmd 能成功；
  6. 放弃修复当前conda环境错误，尝试直接改用新环境： 快速新建一个新环境。
  7. 在新环境中进行执行相关操作，同时帮助学生进行相关测试；

【瓶颈问题】 缺乏ipykernel： vscode直接安装非常慢。 问题原因：网速限制，一般需要首先设置国内PyPI源 指导干预： 考虑到该同学的基础，放弃让其配置PyPI源。直接安装uv（虽然依然是访问国外源，但是可以并发而且使用缓存，一定程度上加快下载），然后使用先进的包解析工具uv 去安装、管理新环境，改为使用命令： uv pip install ipykernel，迅速安装完毕 后续TODO建议: 虽然通过新建环境暂时绕开了问题，但是要求学生后续还要自学真正解决问题。 后续尝试： 代码文件的规范化，使用uv pip 和toml文件，管理依赖

【任务进展】 同学主动给我汇报结果

  • 顺利解决环境问题
  • 利用相同的环境，跑通新的问题–糖尿病预测
  • 程序结构也非常清晰： outline + 每部分代码比较精简 指导干预
  • 梳理还有当前哪些TODO（模型准确率、 图表的中午显示、env环境配置等）
  • 帮同学明确后续优先级（按照同学兴趣— 确定提升模型准确率是后续top1事）

周五： 按照既定任务完成ppt，并尽量提升准确率

** 【瓶颈问题】** ： 为了提升准确率，切换模型后，重新让gpt给他写了一个代码，抓不住核心，两边评测指标不一致 ** 指导干预**

  1. 控制住锚点，要求评测指标、数据集必须固定
  2. 通过把代码变短，抓核心—— 要求整个文件不超过20行（甚至15行代码）
  3. 帮助同学梳理ppt-思路：（数据导入、清洗、训练集测试集划分、模型训练、模型预测、预测结果评估） ——————————————————————————————

最终汇报—— 要求同学用不超过10分钟汇报整个任务的过程、收获

（临时约会，要求同学马上下载腾讯会议，3分钟后上线） ** 同学体会：**

  1. AI完整流程包括： 模型（输入和输出）、策略（损失函数）、算法（找到最佳参数）
  2. 成就：清楚了机器学习的整体流程，通过梳理AI生成的代码，知道每一步在干什么（通过先生成代码，再理解过程的方式，不断推进、不断理解）
  3. 最失败的点、心态：配置环境，环境上出现很多问题（心态上）
  4. 最大的收获： （1）1.学会了利用科学运算库（numpy等）来简化训练代码 （2）利用大模型对代码进行改造优化 （3）将代码进行整合，充分利用在新的模型上

对应的能力 ：

  • 充分利用各种插件、工具
  • 利用大模型辅助，帮助改造优化
  • 代码充分复用
  • 通过重构、拆解学习理解陌生新代码（可以把AI生成的代码看做是完全陌生的新代码）

指导追问：

  1. 为什么要划分训练集和测试集–（基本范式）？为什么要选择这个比例？（80-20）？能否全部都丢到数据集中？对其他数据预测的不是特别好，这里的其他数据怎么理解（真实案例？泛化性）？
  2. 数据清洗，一般有哪些工作？ –怎么定义异常？ 采取了怎样的自动化处理？为什么采用这样的策略？（为什么用中位数，而不是平均数？）
  3. 数据来源，除了文件外，还可以有哪些来源？
  4. 模型的评估：怎么的模型是一个好的模型？
  5. 为什么要可视化？有哪些常见的？有哪些是必要的？
  6. 为什么要做影响因素的分析（业务需要？还是模型剖析的需要？或则好）？还有哪些方法？
  7. 整体流程局限性？
  8. 是否有更多的数据集？ 后续TODO建议: 模型优化换模型； 换数据，补充更多数据；

教学反思：

两种教学模式的对比

模式1：按部就班，先将原理，再让学生动手

理解了每一步后，心里上偏向沉稳，比较稳定。不容易出错

模式2：以任务为驱动，让学生通过解决问题来学习

弊端：（1）每一步其实是再探索–由于根本不知道其基本流程，对相关概念没有认知就动手，思维上一团乱麻，很容易被AI绕进去，心态容易受影响；（2）学生容易满足（感觉在AI帮助下都跑通了），而不愿意再深入研究原理 措施：（1）要求学生通过凝练步骤（不超过5步）来抓核心、自行梳理主要流程；（2）追问实现细节；（3）要求不断迭代优化；
